## Shared implementation seam and exact types

Add one dependency-free classic script, capture-protocol.js, containing frozen constants and pure validation/traversal helpers under globalThis.__cfpProtocol. This is a shared helper inside the existing three-context architecture, not a bundler, RPC framework, service or new execution context.

Required public helper signatures:
- makeTraversal(prep) -> TraversalPlan, the exact frozen type below
- nextFrameSpec(plan, previousAcceptedSpec|null) -> FrameSpec|null
- assertFiniteGeometry(value, fieldName, {positive=false, maximum}) -> number
- validateSnapshot(plan, spec, snapshot) -> {ok, code, retryable}
- frameRect(prep, spec, bitmapWidth, bitmapHeight) -> PixelRect
- novelFrameRect(plan, spec, bitmapWidth, bitmapHeight) -> PixelRect|null; first-writer ownership as specified below
- errorResult(code, message) -> {ok:false, code, error:message}
- getQualifiedCapabilities(target) -> {privateCapture:boolean,preserveVirtualizer:boolean}, from the frozen literal candidate configuration

makeTraversal consumes prep.planId, created once by content preparation, and recomputes all dimensions/steps independently; it does not mint a different planId in each context. Protocol version is the integer 1. Operation/session/plan/document/intent/request tokens are distinct crypto.randomUUID() values. Token strings use the bounded UUID-shaped contract; requestId is a fresh UUID for compositor calls. All numeric inputs must be finite; frame/row/column indices and download IDs are nonnegative safe integers, including zero; sizes are strictly positive.

### Concrete value types, host boundaries and defaults

These are structural JSDoc types in capture-protocol.js, not a TypeScript/bundler migration. Each wire object has only the stated own JSON fields; reject unexpected keys, missing required keys, accessor/prototype surprises, nonfinite numbers and JSON payloads over the relevant bound. Internal DOM objects never cross a port/runtime boundary. An enum is a closed set. Errors use a fixed code-to-text map (maximum 160 characters); never echo a received URL, page string, stack or native message.

- UUID: lowercase RFC-4122 version-4 text, matching `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`. Mint via crypto.randomUUID; fixture UUIDs obey that format and are distinct for distinct roles.
- UInt: Number.isSafeInteger(x) && x>=0. Tab/window IDs use UInt and are checked against tabs.get; do not reject ID 0 by truthiness. RPC sequence is UInt>=1. Dimensions called CSSInt are integers in [1, 16,777,216]; offsets are finite numbers within that absolute bound. Output width <=32767 device px and output pixel count <=200*1024*1024. Validate products as safe integers before allocations.
- ContextKey: `{targetBrowser:"chrome"|"firefox",tabId:UInt,windowId:UInt,incognito:boolean}`. Derived from manifest and actual tabs.get, never caller guesses.
- CaptureIdentity: `{protocolVersion:1,operationId:UUID,sessionId:UUID,owner:UUID}`. owner is worker-lifetime compositorOwner, not content's local Owner object. Worker creates operationId at accepted start and sessionId at each strategy attempt. planId belongs to one completed content preparation. documentNonce belongs to the injected top-frame document for its lifetime. All are separate tokens.
- VisualViewport: null if API absent, otherwise `{scale:number,offsetLeft:number,offsetTop:number,width:number,height:number}` with finite positive dimensions, scale exactly 1, and offsets within 0.5 CSS px of zero. Freeze the observed values and require exact equality across a capture. CSS devicePixelRatio is finite in (0,16]; freeze and compare exactly. No pinch-zoom normalization is attempted.
- Prep: `{protocolVersion:1,operationId,sessionId,owner,planId,documentNonce,strategy:"document"|"expanded-nested"|"preserve",captureScope:"full-page"|"target-only",windowWidth:CSSInt,windowHeight:CSSInt,layoutWidth:CSSInt,layoutHeight:CSSInt,targetWidth:CSSInt,targetHeight:CSSInt,sourceLeft:number,sourceTop:number,clientWidth:CSSInt,clientHeight:CSSInt,direction:"ltr"|"rtl",writingMode:"horizontal-tb",physicalScrollWidth:CSSInt,physicalScrollHeight:CSSInt,devicePixelRatio:number,visualViewport:VisualViewport,geometryGeneration:UInt,warnings:WarningCode[]}`. No old prep.position/scrollerType/scrollX/logicalOffset fields survive. The content context keeps actual scroller/document objects locally. sourceLeft/sourceTop are nonnegative layout-viewport CSS offsets. targetWidth/Height are the frozen finite output extents, never smaller than the target client dimensions. Warnings are deduplicated in fixed lexical order, at most 8 codes. strategy=preserve is the only target-only scope.
- TraversalPlan: `{prep:Prep,planId,width,height,viewportWidth,viewportHeight,maxX,maxY,columns,rows,estimatedFrames}`. width/height map to prep.targetWidth/Height; viewport dimensions map to prep.clientWidth/Height. The frozen Prep is included explicitly so every consumer has source offsets, window dimensions and signature; no consumer reaches for a hidden mutable global. columns/rows are bounded UInt>=1. makeTraversal throws RESOURCE_LIMIT as soon as the count exceeds MAX_CAPTURE_FRAMES; it does not return a partly enumerated plan as usable.
- FrameSpec: `{planId,sequence,row,column,logicalX,logicalY,sourceLeft,sourceTop,clientWidth,clientHeight,stickyCrop:0}`. All fields are reproduced by nextFrameSpec, not accepted from page observations. Logical coordinates are nonnegative CSS offsets measured from the frozen physical left/top of the output, including RTL. source offsets are layout-viewport CSS coordinates; they are not output coordinates. Sequence starts at zero; the next valid sequence is previous+1.
- Snapshot: `{protocolVersion:1,operationId,sessionId,owner,planId,documentNonce,sequence,geometryGeneration,nativeScrollLeft,nativeScrollTop,logicalX,logicalY,windowWidth,windowHeight,layoutWidth,layoutHeight,physicalScrollWidth,physicalScrollHeight,sourceLeft,sourceTop,clientWidth,clientHeight,devicePixelRatio,visualViewport,scrollEpoch,geometryEpoch,warnings}`. The names/types correspond exactly to Prep/FrameSpec, plus finite native scroll values and UInt epochs. Capture-time physical extents must equal Prep's frozen physical extents; any change is GEOMETRY_CHANGED. This intentionally rejects growth as well as shrinkage after freeze rather than silently remapping an existing accepted region. Preparation may settle bounded growth before freeze.
- PixelRect: `{sx:UInt,sy:UInt,sw:UInt,sh:UInt,dx:UInt,dy:UInt}` with sw/sh>=1, represented as half-open source `[sx,sx+sw) × [sy,sy+sh)` and destination `[dx,dx+sw) × [dy,dy+sh)` rectangles in device pixels. No resampling occurs at draw time; source/destination sizes are identical. null is the only empty novel rectangle representation.
- RestoreSummary: `{status:"acknowledged"|"partial"|"failed"|"unverified",restoredCount:UInt,preservedPageChanges:UInt,failedCount:UInt,codes:RestoreCode[]}`. Codes are closed, deduplicated, <=8: DOCUMENT_REPLACED, NODE_REPLACED, PAGE_STYLE_CHANGED, PAGE_SCROLL_CHANGED, STYLE_REMOVE_FAILED, STYLE_RESTORE_FAILED, SCROLL_RESTORE_FAILED, PORT_DISCONNECTED. Preserving a later page edit is a successful ownership decision, not failed restoration. A disconnected caller reports unverified; it must not invent counts from the missing acknowledgment.
- WarningCode is LIVE_MOTION, IFRAME_VIEWPORT_ONLY or TARGET_ONLY_SCOPE. `Error` thrown internally carries a fixed `.code`; rejected API text is never sent as that code. API capability failures are typed before mutation.

Exact function signatures and owners:

- `startCapture(tab, {entry:"popup"|"context-menu"}) -> {operationId,initialized:Promise<PublicStatus>,done:Promise<void>}|null` in service-worker.js. Sets activeCapture synchronously, creates IDs once, validates tab with tabs.get, and settles initialized once after successful compositor start (failure before that rejects). Both entry handlers attach done rejection handling immediately. Preserve native menu ID/title and popup button.
- `createPortRPC(port, identity, operation) -> {call(method,payload),close(reason)}` in worker; its result belongs to the exact GI1 ContentBinding for that port/session. operation supplies the remaining deadline/cancellation; binding-local source-loss handling is registered before prepare and is independent of whether an RPC is pending. tabs.connect uses `{name:"cfp:"+sessionId,frameId:0}` and injection uses target `{tabId,frameIds:[0]}`. Context-menu info.frameId is never forwarded as capture target: right-click inside an iframe still starts the top-page full capture.
- `prepare(owner, {strategy:"auto"|"preserve",prepareExpiresAt,operationExpiresAt}) -> Promise<Prep>` in content. owner is a local object `{identity,cancelled,context}` bound to the validated port. targetElement is never a wire field: internal fallback reuses the original selected Element from owner.context. Public method prepare is called once per port/session.
- Port payloads: prepare as above; position `{spec}`; snapshot `{spec}`; accept-frame `{spec,bitmapWidth,bitmapHeight,rect,novelRect}`; restore `{reason:"success"|"failure"|"cancel"|"fallback"}`; cancel `{reason:CancelReason}`. Responses are Prep, Snapshot, Snapshot, `{acceptedSequence}`, RestoreSummary, and RestoreSummary respectively under the shared response envelope. Unknown method -> INVALID_METHOD. Cancellation/disconnect bypass the queue. A repeated prepare returns ALREADY_PREPARED rather than replacing ownership.
- `moveTo(context,spec) -> Promise<Snapshot>` and `readSnapshot(context,spec) -> Snapshot` in content; `acceptFrame(context,payload) -> {acceptedSequence}` commits only captured candidate/coverage observations retained for that spec. Content cannot fetch/draw pixels or initiate a download.
- `callCompositor(scope,type,payload) -> Promise<validatedResponse>` in worker. Capture scope is the original live operation object; recovery-output scope is an exact internally read OutputEntry/Tombstone; context scope is `{requesterOwner:compositorOwner}`; the fourth, recovery-only AbandonedSessionScope is specified below and authorizes only its generation-bound abort. Do not infer a capture scope from plain JSON. All in-process Firefox calls and Chrome messages use this constructor and one response validator.
- `handleCompositorRequest(envelope, trustedRoute) -> Promise<Response>` in offscreen.js. trustedRoute is a local internal marker chosen only after authenticating the runtime sender, or by `__cfpCompositorHandle` in the already verified Firefox background context. It is never an envelope field. `handle`, createSession and finish raw internals are not callable from production popup/content messages.
- `getBrowserTarget()` requires the Chrome manifest background.service_worker to equal service-worker.js, or Firefox's exact Gecko ID plus the expected background scripts. Ambiguous/neither -> UNSUPPORTED_BROWSER. `getDownloadApi` and private-access checks select chrome or browser using that target. Other existing chrome.* callback/runtime entry points retain their documented cross-browser form.

Sender allowlist selected now: worker popup requests require exact runtime.getURL("popup.html"), same runtime.id, sender.tab absent. Chrome compositor requests require same runtime.id, no sender.tab, and sender.url exactly runtime.getURL("service-worker.js"); URL-absent is rejected until a Q5 specimen plus primary platform evidence justifies a separately reviewed allowlist extension. Firefox production compositor uses only its trusted direct function; do not register an unnecessary Firefox runtime compositor route. Worker Chrome compositor notifications require exact runtime.getURL("offscreen.html"), same runtime.id and no sender.tab. Chrome/Firefox content ports accept same runtime.id and a `cfp:` name followed by exactly one UUID; an absent sender.id is rejected, not treated as a compatibility shortcut. The executing content script also requires window===window.top. Old-shaped input, popup-to-compositor messages and page postMessage never reach mutation.

All request/reply timers settle once, clear on success/failure/cancel, observe late rejection, and reject mismatched identities. Timeout bounds, capped by remaining phase/operation deadlines: content prepare 15,000 ms; position 5,000 ms; snapshot and accept-frame 2,000 ms; restore/cancel cleanup total 2,000 ms; compositor status/list/arm/bind/observe/update/release/abort 2,000 ms; start/frame 60,000 ms; finish min(300,000 ms, remaining operation). The command timeout diagnoses TRANSPORT_FAILED unless its owned phase timer already recorded PREPARE/CAPTURE/ENCODE/OPERATION_TIMEOUT. Cleanup uses its own bounded 2-second grace even after the operation deadline, without permitting further capture/encode/download initiation.

Popup wire format: `{type:"capture-active-tab"|"capture-status",requestId:UUID,windowId:UInt}` or `{type:"capture-cancel",requestId:UUID,windowId:UInt,tabId:UInt,operationId:UUID}`. Reply is `{type,requestId,ok:true,status:PublicStatus}` or `{type,requestId,ok:false,code,error}`. PublicStatus is `{operationId:UUID|null,tabId:UInt,windowId:UInt,incognito:boolean,phase,acceptedFrames:UInt,attemptedFrames:UInt,width:UInt|null,height:UInt|null,warnings,code:string|null,text:string,restoration:RestoreSummary|null}`. operationId is the sole public cancellation handle; owner/session/plan/intent/request tokens for compositor traffic and source URLs are excluded. Phase is idle or one of Package 5's listed phases. Popup ignores stale request IDs, stale tab/window matches, and status for an earlier operation after observing a newer one. Status idle uses text "Ready to capture" plus the restart limitation only when recovery was attempted without metadata. This exact type replaces the ambiguous earlier phrase "no tokens" which would otherwise conflict with operation-bound cancellation.

No persistent format/migration is introduced. Extension update invalidates old content contexts and may destroy URL-owning contexts. Protocol mismatch returns PROTOCOL_MISMATCH and no capture/download, with a popup/badge instruction to reload the affected page. A surviving old offscreen that cannot validate protocol 1 must be allowed its bounded source lifetime; do not force-close unknown retained pixels to make an update succeed. All matching protocol consumers/load-order files ship together.

### LP2: reverse compositor notifications in the existing contexts

Add `notifyWorker(notification) -> Promise<validatedAck>` to offscreen.js. Chrome uses runtime.sendMessage with the existing context-notification envelope and exact offscreen.html sender allowlist at the worker. Verified Firefox shared background calls the locally registered callback instead: [Firefox sendMessage excludes the sending frame](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/runtime/sendMessage), so the two background scripts must not rely on runtime loopback.

offscreen.js exposes `globalThis.__cfpRegisterWorkerNotifications(callback)` only in the verified Firefox background route. Registration creates an opaque local object marker, stores the callback and returns that marker. In service-worker.js, register `handleCompositorNotification(notification,trustedRoute)` synchronously after top-level browser listener registration and before recovery/start can await; retain the returned marker in the worker's lexical state. notifyWorker passes that exact object identity. It is never an envelope field or accepted JSON, and callback invocation must not occur during registration before the marker has been assigned. There is one registered worker callback, replaced only by worker initialization in that same shared context.

Both transports enter the same bounded contextId/lifecycleGeneration/requesterOwner/requestId/payload validator and reconciliation dirty-set scheduler. A valid acknowledgment echoes the normalized notification identity with ok:true,queued:true; it means work was scheduled, not that download search completed. Observe fulfillment/rejection immediately and cap wait at 2000ms. The initial qualified chain has transform/translate/rotate/scale/perspective/filter/backdrop-filter all none, zoom normal or numeric 1, contain none, content-visibility visible, and will-change auto or an explicit list containing none of transform/translate/rotate/scale/perspective/filter/backdrop-filter/contain/content-visibility/zoom. An unknown/computed-unparseable value is indeterminate; do not assume an identity transform has no containing-block effect.
- A definite intervening containing block (for example non-none transform, perspective, or layout/paint containment on a composed ancestor) makes the candidate nonviewport-fixed. Treat its rendered subtree as ordinary page content; never hide it after its first visible fragment. If a containing-block effect is uncertain for the supported platform/profile, classify indeterminate rather than guessing viewport-fixed or hiding it.
- A fixed node in a same-origin iframe is never viewport-fixed under this top-document rule. Its child viewport has no qualified top-viewport suppression translation in this release. Pause styles do not grant suppression authority. Such child content stays ordinary unless its unqualified occlusion requires a typed failure.
- Sticky candidates still require the separate natural-footprint eligibility below. The capture target and any composed ancestor containing it are never suppression candidates. Recheck anchor classification immediately before any opacity-rule mutation, and on each relevant snapshot; a changed mapping invalidates the operation rather than retaining the old classification.

First-global-frame-only fixed suppression is therefore limited to eligible viewport-fixed candidates. Preserve their accepted initial visible fragment and suppress repeats only after accept-frame commits it. Newly appearing/indeterminate fixed candidates are not automatically treated as initial content. Nonviewport-fixed elements are never hidden by this rule. The original-visible-first-viewport limitation remains; it is not permission to hide an unrepresented lower fragment of ordinary document content.

#### G2: natural border bounds versus the suppressed subtree

Store separate local `naturalBorderRect` and `suppressionFootprint` for each eligible sticky/viewport-fixed candidate. Opacity affects the whole rendered subtree, not only the parent's border box ([CSS opacity](https://www.w3.org/TR/css-color-4/#transparency)); bounding rectangles do not expose every possible [ink overflow](https://drafts.csswg.org/css-overflow-3/#overflow-concepts).

Add `measureSuppressionFootprint(element,context) -> {eligible:boolean,footprint:CssRect|null,reason}` using the bounded composed-subtree walker. The initial qualified simple-header class has no generated ::before/::after/::marker content, filter/backdrop-filter, box/text shadow, outline, mask/clip-path, descendant fixed/sticky positioning or nonidentity transform/zoom that could escape/obscure the bound. Every rendered descendant/replaced/text layout rectangle must be contained in the candidate's nontransformed border rectangle. For text-bearing or descendant-bearing candidates, additionally require existing axis-aligned overflow:hidden/clip on both axes with zero corner radii to bound remaining ink; do not add clipping to the page just to qualify it. Empty plain boxes with only bounded background/border paint can qualify without that clipping. If traversal is incomplete, a rendered descendant lies outside the bound, an accessible slot/shadow subtree is indeterminate, or paint effects prevent this qualified bound, return ineligible. This deliberately conservative class can leave an ordinary header unsuppressed; it does not invent a portable complete-paint-bounds API.

For a qualified candidate, suppressionFootprint is its whole proved border rectangle (including the contained subtree); for an ineligible candidate it is null, never a replacement parent-border approximation. Do not hide an ineligible candidate. It may remain visible while no suppression is needed, but when the next capture step requires suppressing an unbounded/unrepresented part to avoid new-pixel occlusion, fail UNSUPPORTED_OCCLUSION before hiding/drawing that step. An unknown footprint cannot be certified harmless merely because its parent box misses the novel strip; conservatively regard potential unbounded ink as intersecting the viewport until a qualified bound is available.

In preparation, compute sticky natural bounds with the owned temporary `position:relative!important;inset:auto!important` rule, read the qualified border/footprint in a read batch, remove the rule and settle before freeze. The target-space origin of a supported top-document rectangle is `(logicalX + rect.left - sourceLeft, logicalY + rect.top - sourceTop)`; widths/heights are CSS lengths. A child-viewport rectangle cannot use that formula without a separately qualified translation, which is not selected here. Keep Element/Document identity, naturalBorderRect, suppressionFootprint and eligibility signature locally.

At position/snapshot retain provisional observations for that exact spec. A qualified sticky footprint is represented only by successfully accepted natural-position pixels, committed by accept-frame. While still naturally positioned, allow additional horizontal frames to acquire its remaining natural footprint; partial representation alone is not unresolved occlusion. Hide only after the whole footprint intersected with frozen output is represented. If it becomes displaced and intersects novel pixels before complete natural representation, fail UNSUPPORTED_OCCLUSION. For coverage/occlusion conversion use conservative floor(left/top), ceil(right/bottom) at the acknowledged actual bitmap ratio, clip only to frozen output, and require the represented device-pixel set to cover that entire quantized footprint. No size-only or border-only coverage shortcut is permitted.

Suppression uses a per-operation random data attribute plus an owned opacity:0!important style rule in the candidate's exact Document/open shadow root. Save prior attribute presence/value and remove/restore only if still owned; never write page inline opacity/animation/transition. Immediately before mutation, recheck anchor and footprint eligibility and identity. If page inline-important opacity or an active transition defeats the rule, leave the candidate unresolved; fail only according to the qualified whole-footprint/unknown-footprint occlusion rule. Content retains compact accepted geometry and candidate records, not screenshot pixels. The first-frame ratio is acknowledged by the compositor; an unqualified first-frame bound cannot gain later suppression eligibility from guessed DPR.

For known bounded unresolved candidates, intersect the entire measured suppression footprint with novelRect mapped to source device pixels; not merely the parent box. For an unknown footprint that might intersect new pixels, fail conservatively. An eligible footprint lying wholly over accepted pixels can remain visible because those pixels are not redrawn. No marker ID, semantic screenshot classifier or arbitrary-overlay recovery is introduced.

Each context caps received future intervals to the policy maximum on first receipt and also measures monotonic elapsed time. Clock going forward may expire early; going backward must not extend an already established local timer.

`MAX_CAPTURE_FRAMES=20000` is a hard geometry cap, not a promise that 20,000 frames fit the ten-minute capture deadline. ### Exact scanline/compressor/IDAT algorithm

Keep one CompressionStream("deflate") per output. Its zlib-wrapped stream spans consecutive IDAT chunks; never use deflate-raw or compress tiles independently. - encodePngChunk(type,payload) -> Uint8Array, retaining testable crc32

For each new tile:
1. Check session/live identity/source not disposed, acquire its Blob and track the local reference.
2. Await createImageBitmap in a try/finally acquisition guard. Immediately after await check both session cancellation and source.disposed before assigning anything.
3. A late decoded bitmap closes immediately. Allocation/getContext/draw failures also close the bitmap even if source state was never fully installed.
4. Draw to one scratch canvas; close bitmap immediately after successful draw. Mark loadedTileIndex and row=0. Delete the savedTiles entry and release its Blob charge only after all local Blob references are cleared.
5. Each pull reads <=16 rows, charges getImageData and filtered output, prepends PNG filter byte 0 per RGBA row and enqueues at most one source-queue chunk with highWaterMark:1. Keep the conservative in-flight pipeline allowance.
6. After final tile row, clear scratch dimensions/context/loadedTileIndex before loading the next tile. End only after all expected rows.
7. dispose first sets disposed=true, then clears synchronous references and marks pending work for late disposal. pull catch calls dispose and errors the source; cancel and encoder finally call the same idempotent function. Do not assume a rejected pull invokes cancel.

Create exactly one compressor, then concurrently:
- retain pipePromise=source.stream.pipeTo(compressor.writable,{signal:sessionPipelineSignal});
- consume compressor.readable using one getReader/read loop, never ReadableStream async iteration.

Do not await pipePromise before reading output, which could deadlock under backpressure. Successful encoding requires readable done and pipePromise fulfilled before final Blob construction. The cumulative encoding deadline also races the foreground orchestration; after failure use the bounded cleanup below rather than hanging on a native read. Late pipe/read results only dispose and cannot settle the operation twice.

collectIdatChunks handles any returned native chunk size. Charge the entire underlying buffer while splitting it into 1 MiB payloads, preserving its reference/charge across yields until every byte is consumed. An empty Uint8Array is skipped, not interpreted as stream completion. After each emitted IDAT, yield with cancellation-aware setTimeout(0); do not discard the unconsumed remainder on a yield. Form each independent PNG chunk with big-endian payload length and CRC(type+payload). Copy final partial staging data into a right-sized chunk and drop staging.

The fixed structure is signature(8)+IHDR(25)+IEND(12), hence:
encodedBytes = 45 + sum(IDAT payload byte lengths) + 12*IDAT chunk count.
Check this at every append and before Blob construction. 128 full 1 MiB payload chunks deliberately exceed the 128 MiB whole-PNG budget; MAX_IDAT_CHUNKS does not waive the byte limit. IHDR is 8-bit RGBA with compression/filter/interlace 0. IDATs are contiguous; IEND is final. Empty image input fails.

Separate successful encoder disposal, finish handoff and cancellation/failure disposal:

- Successful encoding: after readable completion and fulfilled pipePromise, recheck session identity/cancellation/deadline and construct the final Blob with both encoded parts and possible Blob copy charged. Dispose only encoder-owned resources: completed scanline scratch/source state, parts, staging, completed reader/pipe references and timers. Do not cancel/remove/mark unusable the capture session or abort its cancellation signal merely because encoding completed. Return the Blob while retaining its exact charge as session.encodedBlobPendingHandoff, a lease bound to that Blob and the still-live session identity. Dropping encoder buffers must not debit this lease. No one-tile passthrough optimization is selected.
- Finish handoff: immediately recheck live session identity, cancellation and deadline, and require the returned Blob to match the successful encodedBlobPendingHandoff lease. In one synchronous handoff with no await, create its URL, insert the exact encoded ledger entry, and transfer that same lease from the session to the ledger. Clear the session's pending-handoff slot and local Blob reference. Only afterward may capture-session cleanup remove capture state; it must not release/debit the transferred output lease. There is no earlier transfer simply because encodePngFromTiles returned.
- Handoff failure: if URL creation or ledger insertion fails, remove only any exact newly inserted entry from this attempted handoff, revoke any URL newly created by it, clear local/pending Blob references and release that pending lease exactly once. No orphan URL/entry/charge and no change to older outputs is permitted.
- Cancellation between successful encoding and finish insertion: drop/release the pending Blob once, perform cancellation cleanup and create no URL. A completed scanline source's disposed flag alone is not this cancellation; source.disposed prevents late pull/decode/enqueue but does not invalidate a successful Blob.
- Cancellation or source/sink/read/allocation/CRC/Blob failure: mark the capture session unusable, abort the shared pipeline signal, call reader.cancel with rejection observed, and call source.dispose. Retain truthful pending-native-disposal charges. This failure path, not successful encoder-only disposal, invalidates the session.
- Do not call readable.cancel while its reader owns the lock or separately abort the locked compressor writable. Observe pipePromise and reader cancellation immediately. Release the reader lock after the read/cancel operation settles where required; if settlement exceeds the 2000 ms cleanup wait, attach late finally/rejection handlers to perform release/disposal. Do not claim a pending read lock was released while the platform forbids it.
- Failure cleanup wait remains capped at 2000 ms with an owned clearable timer. A timeout settles foreground cleanup once but keeps pending-disposal charges/late handlers; late results only dispose and cannot create an output URL.
- Erroring pull, already-aborted signal and rejecting cancel use that failure path with zero unhandled rejections. Successful cleanup of a fulfilled pipeline neither enters failEncoding nor aborts the live session.

Native compressor/decoder/GPU memory and transport temporaries remain outside fully observable JS accounting. No counter or final Blob proves a hard process-memory ceiling.
